# Be the Borrow Checker

A Rust quiz where you play the compiler. Each round shows a short program and
asks one of three things:

- **Verdict:** does it compile? Stamp it accepted or rejected.
- **Output:** what does it print (or does it fail to compile, or panic)?
- **Fix it:** the program is rejected. Which replacement for one line makes it
  compile and print the expected text?

After every answer the game shows an explanation and the real `rustc` output.

The chapters follow the order of [The Rust Programming Language](https://doc.rust-lang.org/book/)
("the book"), and each one names the book chapters it draws on. The chapters
about tooling and the longer projects are covered through the language
features they introduce, since a quiz question has to be one short program.

Play it at <https://reinhash.com/demos/be-the-borrow-checker/>.

## Every answer is checked by rustc

The questions live in [`src/questions.ts`](src/questions.ts). Nothing in them
is taken on trust: `npm run verify` compiles every program with your local
`rustc`, runs the ones that compile, and fails if any claim is wrong:

- whether the program compiles,
- the code and line of the first error,
- the printed output, or that it panics,
- that a fix question has exactly one choice that compiles and prints its goal,
- that programs which compile do so without warnings.

A question marked `test: true` is built with `rustc --test` and its tests are
run, the way `cargo test` would. Its outcome is the test summary, for example
`1 passed, 1 failed`, and that is what the answer choices are checked against.

What `rustc` said is written to `src/verified.json`, and the game shows that
output after each answer. The file records the compiler version it was made
with. Error codes and line numbers can change between Rust releases, so a
newer `rustc` may need a few expectations updated.

## Development

You need Node.js and a Rust toolchain (`rustc` on your `PATH`).

```bash
npm install
npm run dev      # local server with reload
npm run verify   # compile and run every program, rewrite src/verified.json
npm test         # check that verified.json matches the questions (no rustc needed)
npm run build    # verify, test, typecheck, then build dist/index.html
```

The build produces a single self-contained `dist/index.html`.

## Adding a question

Add an entry to a chapter in `src/questions.ts`, then run `npm run verify`.
The three shapes are described in [`src/types.ts`](src/types.ts):

```ts
{
  id: "move-string",            // unique across the whole quiz
  kind: "verdict",              // or "output" or "fix"
  topic: "Move",                // short label on the card
  code: rs`
    fn main() {
        let a = String::from("crab");
        let b = a;
        println!("{a} and {b}");
    }
  `,
  expect: { ok: false, error: "E0382", line: 4 },
  explain: "`let b = a` moves the `String`. ..."
}
```

A few rules the checks enforce:

- Programs are one file, standard library only, at most 54 columns wide.
- A program that compiles must compile without warnings.
- Explanations use `backticks` for inline code and should explain each term
  in plain words the first time it comes up.

If `verify` disagrees with your expectation, it prints what `rustc` actually
reported, so the quickest way to write a question is to guess and run it.
